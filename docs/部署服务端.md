# 部署服务端

> ⚠️ **先看这条**：客户端把地址写死了 —— `petclub/config.py` 里
> `SERVER_HOST = '47.94.21.34'` / `SERVER_PORT = 8765`。它**不会**问你填哪个服务器。
> 所以「自己部署一套」意味着：部署完之后，还要把这两行改成你的地址、重新打包客户端，
> 否则你部署的服务端没有客户端会连过来。本文下面的步骤都是围绕「怎么让服务端稳定跑着」。

服务端是 `server.py` 一个文件，**只用标准库**，不需要装 Pillow，不需要数据库。

先说清它是什么：

| 它做的事                     | 它不做的事               |
| ------------------------ | ------------------- |
| 裁决谁占了哪个身份（p1 ~ p4，先到先得） | 不存任何数据，没有数据库、没有磁盘文件 |
| 把「谁在线」实时推给所有人            | 不做账号、不做鉴权、不加密       |
| 转发互动事件（`to` 为空就广播给其他人）   | 不管画面、不管动画，那些全在客户端   |

由此推出两条必须知道的结论：

1. **一台服务器就一个房间，最多六个人**（只有六个身份）。想让两拨人各玩各的，就在不同端口起第二个服务端。
2. **服务端重启 = 房间清空**。所有客户端会自动重连（3 秒起、退避到 20 秒），重连后重新认领身份。所以重启不算事故，但正在飞的动作会断。

## 一、局域网（同一 WiFi / 同一办公网，最常用）

几个人在同一个网里，找一台机器当主机就行，谁开都行。

### 1. 在主机上启动

双击 `启动服务端.bat`，或者命令行：

```bat
py server.py --host 0.0.0.0 --port 8765
```

- `--host 0.0.0.0` 是**关键**：监听所有网卡。如果写 `127.0.0.1`，只有本机能连，别人连不上。
- `--port 8765` 可以换，换了之后客户端也要跟着换。
- `启动服务端.bat` 会先把本机 IPv4 打出来，那个地址就是别人要填的。

启动成功长这样：

```
[21:03:11] pet-club 服务端已启动：0.0.0.0:8765
[21:03:11] 身份：p1=猥琐、p2=胡大神、p3=杨大师、p4=婧婧
```

### 2. 放行防火墙端口

Windows 默认会拦入站，这一步不做，别人就是「连不上」。

图形界面：Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口 `8765` → 允许连接 → 三个网络都勾上。

或者一条命令（管理员 PowerShell）：

```powershell
netsh advfirewall firewall add rule name="pet-club 8765" dir=in action=allow protocol=TCP localport=8765
```

删掉这条规则：

```powershell
netsh advfirewall firewall delete rule name="pet-club 8765"
```

### 3. 让客户端连到你自己的服务端

客户端没有输入框，只能改代码：

```python
# petclub/config.py
SERVER_HOST = '192.168.1.20'    # 主机 IP（ipconfig 里的「IPv4 地址」）
SERVER_PORT = 8765
```

改完重新打包发给队友。**别填 `127.0.0.1`** —— 那是「我自己」，队友那边指的是他自己的机器。

### 4. 连不上怎么查

按这个顺序，一步就能定位：

```powershell
# ① 主机上：服务端真的在听吗
netstat -ano | findstr 8765

# ② 别人机器上：端口通不通（通 = TcpTestSucceeded: True）
Test-NetConnection 192.168.1.20 -Port 8765
```

- ① 没输出 → 服务端没起来，或起在了 `127.0.0.1`。
- ① 有、② 不通 → 防火墙拦了，回第 2 步。
- 都通但客户端还报连不上 → 大概率是路由器开了「AP 隔离／访客网络」，或者两台机器不在同一网段。

## 二、公网（云服务器，人不在一个网里）

最低配就够：1 核 1G、1M 带宽。服务端只转发几十字节的 JSON，几乎没有负载。

### 1. 传上去、装 Python

```bash
scp server.py root@你的服务器:/opt/pet-club/
ssh root@你的服务器
apt update && apt install -y python3        # 一般已经自带
python3 --version                            # 需要 3.8 以上
```

### 2. 开安全组 + 系统防火墙

- 云控制台的**安全组**里放行入方向 TCP `8765`（这一步最容易忘，安全组优先级高于机器自己的防火墙）。
- 机器上如果开了 ufw：`ufw allow 8765/tcp`。

### 3. 先手动跑一次，确认能

看到「服务端已启动」就说明环境没问题，`Ctrl+C` 停掉，接着配常驻。

### 4. 配成系统服务（开机自启 + 崩了自动拉起）

`/etc/systemd/system/pet-club.service`：

```ini
[Unit]
Description=pet-club server
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/pet-club
ExecStart=/usr/bin/python3 /opt/pet-club/server.py --host 0.0.0.0 --port 8765
Restart=always
RestartSec=3
StandardOutput=append:/var/log/pet-club.log
StandardError=append:/var/log/pet-club.log

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now pet-club
systemctl status pet-club              # 看是否 active (running)
tail -f /var/log/pet-club.log          # 看认领/断开的实时日志
```

日志长这样，能直接看出谁在什么时候进来、谁掉了：

```
[21:03:41] 认领「胡大神」
[21:05:02] 互动 drink → 2 人
[21:06:19] 「胡大神」心跳超时，踢出并释放
```

### 5. 更新服务端（改了 server.py 之后）

服务端只有一个文件，更新就是「换文件 + 重启」：

```bash
scp server.py root@你的服务器:/opt/pet-club/     # 1. 换文件
systemctl restart pet-club                      # 2. 重启
tail -n 20 /var/log/pet-club.log                # 3. 确认跑的是新文件
```

第 3 步必须看这两行 —— 启动日志会把当前生效的身份表打出来，
**改了 ROLES 却没重启，或者传错了文件，一眼就能看出来**：

```
[14:41:02] pet-club 服务端已启动：0.0.0.0:8765
[14:41:02] 身份：p1=猥琐、p2=胡大神、p3=杨大师、p4=婧婧
```

顺便确认端口在听：`ss -lntp | grep 8765`。

**三条命令的分工，别混**（第一次配常驻和「改完代码要生效」是两件事）：

| 命令 | 干什么 | 什么时候用 |
|---|---|---|
| `systemctl daemon-reload` | 重新读 `.service` 文件 | **只在改了 unit 文件**之后。没动 unit 就不必跑（跑也无害） |
| `systemctl enable --now pet-club` | 设开机自启 + 「没在跑就现在起来」 | 首次安装。**已经在跑时它什么都不做** |
| `systemctl restart pet-club` | 停掉再起 | **改完 `server.py` 必须用它** |

最常见的坑就是：改完 `server.py` 跑了 `enable --now`，命令没报错，
于是以为生效了 —— 其实进程根本没换，行为当然还是老的。

**重启的副作用**：房间在内存里，重启 = 清空。所有客户端 3 秒内自动重连
并重新认领（它们记得自己是谁），冷却和飘着的动作会重置。
日志里会看到一串「连接断开」+「认领」，属于正常现象，不是事故。

### 6. 客户端怎么指向这台服务器

**客户端不接受任何地址配置**：地址写死在 `petclub/config.py` 的
`SERVER_HOST` / `SERVER_PORT`，界面上没有输入框，也没有配置文件和环境变量可覆盖。
要给自己的服务器用，就改这两行然后重新打包（`python tools/build_app.py`），
再把 `dist/pet-club.exe` 发给所有人。

## 三、家里电脑 + 内网穿透（不想买服务器）

家里机器没有公网 IP，用 frp 之类把端口穿出去，思路是：**云上一台小机器跑 frps，家里跑 frpc 指向本机 8765**。

`frpc.toml`（家里，新版 frp 用 toml）：

```toml
serverAddr = "你的云服务器IP"
serverPort = 7000

[[proxies]]
name = "pet-club"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8765
remotePort = 8765
```

云上 `frps.toml` 写 `bindPort = 7000`，安全组同时放行 7000 和 8765。起来之后客户端填云服务器的 `IP:8765` 即可。

代价：家里那台机器必须一直开着，且网络抖动会直接反映成断线重连。

## 四、安全与运维

**它没有鉴权，也没有加密。** 谁连上谁就能认领身份、给所有人发互动。所以：

- 不要用默认端口裸奔在公网。改个端口 + 安全组只放行你们几个人的出口 IP，成本最低。
- 几个人的小工具，做到这一步就够了；真要防，就套 frp/stunnel 做 TLS，或者上 VPN。
- 互动文本服务端会收敛（去多余空白、截断到 200 字），但不能当输入过滤用。

**日常维护基本没有：**

| 想做的事  | 怎么做                                                                 |
| ----- | ------------------------------------------------------------------- |
| 看谁在线  | 客户端右键自己 →「服务器成员」，或看服务端日志                                            |
| 重启服务端 | `systemctl restart pet-club`，客户端自动重连（`enable --now` 不行，详见 5 条）  |
| 换服务器地址/端口 | 服务端改 `ExecStart` 里的 `--port`；客户端改 `config.py` 的 `SERVER_HOST`/`SERVER_PORT`，必须**重新打包**所有人换 exe |
| 身份被占死 | 不用管：30 秒没心跳会被巡查线程踢掉并释放身份                                            |
| 端口冲突  | `netstat -ano \| findstr 8765`（Win）/ `ss -lntp \| grep 8765`（Linux） |

**心跳参数**（`server.py` 顶部，改完要重启服务端）：

| 常量                   | 默认   | 含义                    |
| -------------------- | ---- | --------------------- |
| `HEARTBEAT_TIMEOUT`  | 30 秒 | 超过这么久没心跳 = 掉线，踢出并释放身份 |
| `REAP_INTERVAL`      | 5 秒  | 巡查间隔（改完要等当前这一轮睡完才生效）  |
| `IDLE_TIMEOUT`       | 90 秒 | 连上却一直不发消息的连接超时断开（客户端心跳 5 秒一次，正常不会有连接撞上它） |
| `request_queue_size` | 64   | 并发握手排队长度，几个人同时启动也不会被拒 |

## 六、CentOS 8：服务端 + 网页版（最简部署）

服务器上跑两个进程，都只用标准库 —— **CentOS 8 自带的 Python 3.6 直接能跑，
不需要 pip install，也不需要升级 Python**。

| 进程 | 端口 | 谁在用 |
| --- | --- | --- |
| `server.py` | 8765 | 桌面版直连（裸 TCP），同时是网页版的上游 |
| `web_gateway.py` | 8766 | 网页版：HTTP 页面 + WebSocket 桥（不解析业务消息） |

网页版和桌面版共用同一个房间：网页上认领 p1，桌面端就看到 p1 在线（反之亦然）。
两边身份互斥，本地聊天记录各自独立。

### 1. 上传这些文件（保持目录结构）

```
server.py
web_gateway.py
petclub/__init__.py      # 只为了 __version__，整个 petclub/ 传上去也行
petclub/actions.py       # 指令/台词，网页的 /api/meta 从这里取
web/                     # 网页本体（index.html、js/、style.css）
assets/                  # 角色立绘、表情包、图标（约 6 MB）
deploy/                  # start.sh / stop.sh / status.sh
```

本地执行一条 scp 就够（在项目根目录）：

```bash
ssh root@47.94.21.34 "mkdir -p /opt/pet-club"
scp -r server.py web_gateway.py petclub web assets deploy root@47.94.21.34:/opt/pet-club/
```

首次部署这样传一次就行；之后改版用 `发布网页版.bat`（见第 5 节），
它打成一个包传，不会再把 170 多个文件逐个握手。

### 2. 一键启动

```bash
ssh root@47.94.21.34
cd /opt/pet-club
sh deploy/start.sh          # 起 8765 + 8766，PID 在 run/，日志在 logs/
sh deploy/status.sh         # 看进程、端口、网页 200 自检、最近日志
sh deploy/stop.sh           # 停掉两个进程
```

`start.sh` 用 `nohup` 起后台进程，关掉 SSH 不会退出；重复执行不会起第二份。
启动成功会直接打印网页地址：

```
== 启动完成 ==
  网页版：    http://47.94.21.34:8766/
  桌面端连：  47.94.21.34:8765
```

### 3. 放行端口（两步都要做）

```bash
# 机器自己的防火墙（CentOS 8 默认 firewalld）
firewall-cmd --permanent --add-port=8765/tcp
firewall-cmd --permanent --add-port=8766/tcp
firewall-cmd --reload
firewall-cmd --list-ports
```

然后到阿里云控制台的**安全组**里放行入方向 TCP `8765`、`8766`
（安全组优先级高于机器防火墙，只配一边最常见的现象就是「本机 curl 通、外网打不开」）。

### 4. 验证

```bash
curl -I http://127.0.0.1:8766/                  # 期望 200
curl -s http://127.0.0.1:8766/api/version       # 期望 {"version":"1.7.1","build":"..."}
curl -s http://127.0.0.1:8766/api/meta | head   # 能看到 server_version/web_version/build
```

浏览器打开 `http://47.94.21.34:8766/` → 选一个身份 → 进聊天界面。
桌面版仍然连 `47.94.21.34:8765`，客户端不用改。

### 5. 更新版本

**日常不用再往 MobaXterm 里拖文件了，双击项目根目录的 `发布网页版.bat`。**

它做四件事：

1. 校验 `petclub/__init__.py`、`petclub/config.py`、`server.py` 三处版本号是否一致
   （对不上直接退出，不会把半套代码传上去）
2. 按 `web/` + `assets/` 的内容算一个 build 号，写进 `web/build.json`
3. 打成**一个** tgz（约 4.8 MB、180 个条目，含素材），scp 传上去，远端解压覆盖 ——
   不再是 170 多个文件逐个握手
4. 重启两个进程

```bat
发布网页版.bat          改过 .py（或不确定）用这个：传完重启，最稳
发布网页版.bat fast     同样全量传，但不重启。仅限没动过 .py 的时候
```

**每次都是全量：代码 + 网页 + 素材一起发。** 素材不做增量、也不单独发，
理由不是省事，而是「线上到底是哪一版」必须只有一个答案：拆开传迟早停在
「新 JS 配旧图片」，而且事后没法从服务器反推出它对应哪个提交。
PNG 已经压过，gzip 只把 180 个条目收成一个流，6 MB 网络上一两秒。

第一次跑要输服务器密码，想省掉就配 SSH 公钥（`ssh-copy-id`）。
脚本顶部的 `HOST` / `USER` / `PORT` / `REMOTE` 改成自己的。

**只想换几张图、不想重启也不想打 tag** 时，用 `发布素材.bat`：它只传
`assets/` + 重算后的 `build.json`，同样会让已打开的页面提示刷新
（素材也参与 build 指纹，图片 URL 上挂着 `?v=<build>`，换图不会卡在
浏览器那 1 小时缓存里）。

已经打开的网页会在 1 分钟内发现 build 号变了：

- 标签页在后台 → 直接刷新，切回来就是新版
- 用户正看着 → 底部弹一条「新版本 x.y.z 已发布 / 立即刷新」
- 刷新后自动坐回原来的身份，不用重新选

桌面端不受影响，仍然要重启客户端（它有自己那套 `tools/make_release.py` 流程）。

> 为什么重启不是可选项：`web/` 和 `assets/` 是每次请求读盘的，换掉就生效；
> 但 `.py` 早被解释器读进内存了，不重启等于没传 —— 这正是「客户端是新的、
> 服务端还是旧的」那类最难查的故障来源。

#### 让打 tag 自动发（GitHub Actions）

配好之后，推一个 `v*` tag 就自动跑 `.github/workflows/deploy-web.yml`：
校验版本号 → 打包（全量，含素材）→ 上传 → 重启 → 从外面核对线上 build 号。
它和 `build.yml`（打 exe / .app）是两条腿，互不等待。

包内固定是 `server.py web_gateway.py petclub/ web/ deploy/ assets/`，
不含 `__pycache__` 和 `assets/_gen`（做图预览，.gitignore 里也忽略了）。
打包这一步会自己数 `assets/roles`、`assets/stickers`、`web/js`、`web/build.json`
的条目数，少一个就中止 —— 素材漏了的表现是「代码是新的、图全 404」，
等发布完才发现就晚了。

一次性准备：

1. 生成一把**只给部署用**的密钥，别复用你天天登服务器的那把：

```bash
ssh-keygen -t ed25519 -C "github-deploy" -f ~/.ssh/petclub_deploy -N ""
ssh-copy-id -i ~/.ssh/petclub_deploy.pub root@47.94.21.34
```

第一条只生成一对密钥（`-N ""` 表示不要口令，CI 里没法输口令）；
第二条把**公钥**追加进服务器的 `~/.ssh/authorized_keys`，会要一次服务器密码。

2. 把**私钥**全文放进 Secret。私钥是多行文本，别手打，直接复制：

```bash
cat ~/.ssh/petclub_deploy | clip          # Windows；macOS 用 pbcopy
```

3. 仓库 → Settings → Secrets and variables → Actions → New repository secret，
   逐个加：

| Secret | 值 |
| --- | --- |
| `DEPLOY_HOST` | 服务器 IP |
| `DEPLOY_USER` | 登录用户 |
| `DEPLOY_KEY` | `~/.ssh/petclub_deploy` 的全文（含 `-----BEGIN...` 和 `-----END...` 两行） |
| `DEPLOY_PORT` | 可选，默认 `22` |
| `DEPLOY_PATH` | 可选，默认 `/opt/pet-club` |

`DEPLOY_KEY` 粘贴时保留首尾两行和中间的换行，末尾多一个换行没关系
（workflow 里用 `printf '%s\n'` 写文件，不会缺结尾换行导致 `invalid format`）。

4. 安全组把 22 端口放开给 GitHub 的 runner。只放行了自己公司或家里 IP 的话，
   workflow 会卡在「准备 SSH」—— 这是最常见的失败原因。

配完先本地验一把密钥，别等到打 tag 才发现：

```bash
ssh -i ~/.ssh/petclub_deploy -o IdentitiesOnly=yes root@47.94.21.34 "echo ok"
```

要密码就说明公钥没装进去（`ssh-copy-id` 那步没成功）；打印 `ok` 就对了。
`-o IdentitiesOnly=yes` 是为了排除「本机其他密钥先被试了」的干扰 ——
GitHub 上只有这一把，没这个变量会看到不一样的结论。

之后 `git tag v1.7.0 && git push origin v1.7.0` 就发完了。

两条硬约束：

- **tag 和代码版本号必须一致。** `v1.7.0` 配上代码里的 `1.6.0` 会直接失败，
  否则线上就变成「网页说 1.7、服务端说 1.6」。
- **回滚**：在 Actions 里手动跑这个 workflow，ref 选旧 tag 重发一次。
  build 号跟着变回旧值，已经打开的页面会提示刷新。

> 这把密钥等于服务器 root 权限。GitHub 账号务必开 2FA；想更稳就在
> Settings → Environments 建一个 `production`，给 workflow 加一行
> `environment: production`，之后每次发布都要人工点一下才走。

### 6. 开机自启（可选，一行）

不装 systemd 也能自启，用 root 的 crontab：

```bash
(crontab -l 2>/dev/null; echo "@reboot cd /opt/pet-club && sh deploy/start.sh") | crontab -
```

要「崩了自动拉起」再上 systemd（两个 unit，`Restart=always`，`WorkingDirectory=/opt/pet-club`，
`ExecStart=/usr/bin/python3 /opt/pet-club/web_gateway.py --host 0.0.0.0 --port 8766`，
另一个跑 `server.py`）。

### 7. 排错顺序

1. `sh deploy/status.sh` —— 进程在不在、端口有没有监听、网页是不是 200。
2. 本机 `curl` 通、外网不通 → 安全组没放行（最常见），或 `firewall-cmd` 没 reload。
3. 网页能打开但一直「正在连接」→ 看 `logs/server.log` 里 8765 起没起；网关连不上上游会打
   `连不上上游 127.0.0.1:8765`。
4. 端口被占：`ss -lntp | grep -E '8765|8766'`，换端口时 `SERVER_PORT=9000 sh deploy/start.sh`
   （网关的上游会跟着变；此时桌面端也要改地址重新打包）。
