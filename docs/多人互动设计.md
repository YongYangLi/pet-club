# pet-club 多人互动设计

## 一、核心设定

**一台服务器就是一个房间。** 没有房间码、没有昵称，只有「身份」。

| | 单机桌宠（desk-pet-lite） | pet-club |
|---|---|---|
| 一台电脑上养几只 | 三只全养 | 只养自己认领的那一只（别人的也显示，但不受你控制） |
| 怎么进同一个场 | — | 打开客户端（地址写死） |
| 身份 | 无 | 三个固定身份，认领制，**全局唯一** |
| 桌面上站着谁 | 自己的三只 | **这台服务器上所有被认领的角色** |

由此推出三条硬约束：

1. **一个服务器最多 3 个人**（只有 3 个身份），身份不重复由服务端裁决。
2. **不需要分发素材**：每个人用的都是内置的 p1 ~ p4，谁的机器上都有。
3. **桌面是公共空间**：别人认领的那一刻，他的角色就出现在你的桌面上。
   所以「谁在线」不需要一份单独的名单 —— 桌面本身就是名单。

## 二、为什么绕不过服务器

A 和 B 同时点「我要当猥琐」时，**只有第三方裁判能判定谁先到**。
让两个客户端互相问「你占了吗」必然出现双占：网络有延迟、两边时钟不一致、
两条消息可能同时在路上。占用判定必须在一个串行点上完成 —— 这就是 `server.py`。

服务端只做三件事，但每件都是必须由它做的：

| 职责 | 为什么客户端做不了 |
|---|---|
| 身份唯一性裁决 | 需要原子操作，客户端之间没有共识机制 |
| 在线状态判定 | 「他还在不在」需要一个中立的心跳接收方 |
| 状态与事件广播 | 双方可能在不同网络，互相看不见 |

### 僵尸占用

人掉线了但没点退出，身份会被永远占死。所以每个成员带 `last_seen`，
巡查线程发现超过 `HEARTBEAT_TIMEOUT`（30 秒）没心跳就踢掉并**释放身份**。
没有这段，用几天就会出现「所有人都离线却没人能认领那个身份」。

## 三、通信协议

一条 TCP 长连接，每条消息是一行 JSON（UTF-8，`\n` 结尾）。

### 客户端 → 服务端

| t | 字段 | 说明 |
|---|---|---|
| `join` | `role` | 认领身份（`p1` ~ `p4`） |
| `ping` | — | 心跳，每 5 秒一次，**每一条连接都发**（包括还没认领身份的 —— 否则坐在认领窗里的人会被 `IDLE_TIMEOUT` 当僵尸踢掉） |
| `event` | `kind` `text` `to`(可选) `mt` `img` `name` `size` | 发起互动，`to` 省略则发给所有人；`mt` 见下面的「消息类型」 |
| `leave` | — | 主动释放身份 |
| `query` | — | 主动要一次状态（连上时服务端也会自动推） |

### 服务端 → 客户端

| t | 字段 | 说明 |
|---|---|---|
| `state` | `players` `online` `total` | 各个身份谁被认领了；**连上即推**，变化时广播给所有人 |
| `joined` | `role` `name` | 认领成功 |
| `reject` | `reason` `role` `msg` `players` | 认领被拒（`role_taken` / `bad_role`），附带最新占用情况 |
| `event` | `kind` `from` `text` `to` `mt` `img` `name` `size` | 别人发来的互动。`to` 是收件人身份，`null` = 发给所有人（聊天面板靠它区分单聊和群聊） |
| `error` | `msg` | 这条没被接受（附件太大 / 格式不对 / 还没认领身份），客户端会把 `msg` 显示在聊天窗的提示行上 |
| `pong` | — | 心跳应答 |
| `left` | — | 释放确认 |

### 消息类型（`mt`）

`kind='say'` 的那一条可以是四种东西。`mt` 缺省 = `text`（老客户端从不发它）。

| mt | 带什么 | 上限 | 说明 |
|---|---|---|---|
| `text` | `text` | 200 字 | 普通一句话 |
| `img` | `img`（base64） | 1.2 MB | 图片，客户端发之前已缩到 1280px 长边 |
| `sticker` | `img`（base64） | 300 KB | 角色表情包（256×256 PNG） |
| `emoji` | `text`（一个字符） | — | **不带附件**：对面用本机字体渲同一张脸 |
| `file` | `img` + `name` + `size` | 2 MB | 原样传，收下后落到本地附件目录 |

`img` 是 base64 字符串，服务端只做三件事：长度不超过 `MAX_IMG`、
字符集合法（`^[A-Za-z0-9+/]+={0,2}$`）、原样转发。它不认识图片格式，也不需要认识。

空 `text` 的 `text` 消息会被丢弃；`emoji` 必须带一个非空 `text`。


`players` 是一个按 `ROLES` 展开的字典（现在是四键）：被认领是 `{"role": "p1", "name": "猥琐"}`，空闲是 `null`。
**被认领就等于在线** —— 掉线的人会被巡查清走并释放身份，不会留下假在线。

`state` 广播给**所有连接**，不只是已认领的人 —— 认领界面要靠它把已被认领的卡片灰掉，
而且别人先认领时，你还开着的认领窗能实时更新。

## 四、桌面上的行为

### L0 出场

新人认领的那一刻，他的角色在**所有人**的桌面上从屏幕上方落下（`fall.png`），
落地换成 `idle`。自己的角色同样如此 —— 出场方式统一，不用区分「这是我」。
身份按 `ROLES` 的顺序在屏幕底部均分（五个身份就是 1/6、2/6、3/6、4/6、5/6），
这是**初始站位**：
所以刚上来时每个人看到的布局是一致的，也不会互相踩。

**但位置是本地的，不上报。** 谁都可以按住自己的（或别人的）角色把它拖走、
再松手扔回地面，这只改自己屏幕上的窗口位置，别人那边毫无变化。
这是有意为之 —— 「摆弄自己桌面上那只」属于单人乐趣，同步它反而会让
「我刚才明明把它挪到左边了」变成一场三方拉扯。代价是三个人看到的布局
可能不一样，口头描述位置时要记得这一点。重新入场（掉线重连 / 换身份）
会回到初始站位。

只显示**已被认领**的角色：空着的身份不在桌面上占位。

### L1 状态可感知

- 有人认领 → 他的角色落下来（这本身就是提示，不需要再弹文字）
- 有人离开 / 掉线 → 角色消失，身份回到可认领
- 「谁在线」只在聊天面板里看：右侧标题行的「N/5 在线」胶囊；右键菜单顶部只写
  「我 → 全员」，不再列成员名单（只列人、不显示服务器地址）

### L2 互动（详细设计见 [互动玩法设计.md](互动玩法设计.md)）

v2.3 起界面不再分层，全部收进同一份右键菜单 —— 右键谁就作用在谁身上。
v2.9 起**没有「不出门」这一类**：九条指令全部发一条 `event`，
收到的一方让「发起者角色」和「自己的角色」一起做（`mirror`）。
以前那四条「只在我屏幕上」的动作去掉了 —— 对方毫无感知的互动，看起来是假的。

### L3 全员同步（需要服务端带时间戳广播）

这类玩法的前提是「所有人同时看到同一件事」，所以要由服务端下发一个
带时间戳的事件，各客户端按本地时间对齐后一起演。

- **集合**：全员在线时，各人自己屏幕上的角色同时走到屏幕中央
- **一起跳 / 一起睡**：倒数后同时做同一个动作
- **接力打招呼**：A 挥完 B 挥，服务端按顺序转发

### L4 彩蛋

- 全员在线满 N 分钟触发一段集体演出
- 某个身份被两个人抢（服务端拒绝的那一刻，本身就是个可玩的场景）

## 五、分期

| 阶段 | 内容 | 状态 |
|---|---|---|
| **P0** | 服务器即房间、认领身份、身份唯一、桌面常驻已认领角色、天降出场 | ✅ 已完成 |
| **P1** | 互动玩法 v2：自己玩 / 一起玩两层 + 12 个动作 + 互动面板 | ✅ 已完成 |
| **P2** | 动作冷却与防刷屏；断线重连的体验打磨 |
| **P3** | L3 全员同步玩法（需要带时间戳的广播）、播放声音 |
| **P4** | 账号体系、自定义角色导入与分发、公网部署 |

## 六、已知限制与待定项

1. **掉线重连后身份可能已被别人拿走**：现在会走 `reject` 分支，
   客户端弹认领窗让用户重选。体验上还可以更友好（比如自动换一个空闲身份）。
2. **同一台机器同时只能开一个客户端**：还没做单实例保护，同时开两个会打架
   （两个进程抢同一个身份，后开的会被服务端拒绝，但本地窗口会重影）。
3. **服务端没有持久化**：重启后身份全部释放，成员需要重新认领。这在小规模下够用。
4. **没有身份认证**：谁连上服务器，谁就能认领一个空着的身份。
   要对外发布，这层必须补。
5. **明文传输**：`event` 的文本在网络上是明文。
6. **认领窗开着时别人抢了同一个身份**：靠 `reject` 兜底，会带着最新状态重开一次。
